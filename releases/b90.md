## Angels95 b90

Changes since [b89](https://github.com/odelyzid/angels-95-omega-tech/releases/tag/b89) - [compare](https://github.com/odelyzid/angels-95-omega-tech/compare/b89...b90)

The editor architecture refactor reaches its designed shape, and two long-standing
selection bugs are fixed. One of those had been silently mis-deleting brushes.

### Fixes

- **fix(editor)**: make `SelType::BRUSH` mean a renderable index, and nothing else ([712d1f9](https://github.com/odelyzid/angels-95-omega-tech/commit/712d1f9))
- **Pressing Delete could remove a different brush than the one selected.** Two raycasts
  both returned `SelType::BRUSH` with incompatible indices: `RaycastTestBrushes` with a
  `GetCollisionVolumes()` index (the CSG **output**, merged AABBs) and
  `RaycastTestOzPrimitives` with an `m_renderables` index. A brush's volume and its own
  mesh AABB occupy nearly the same space, so which index you got was decided by a
  sub-pixel distance difference. `AngelEd.log` from a real session shows four clicks on
  one point producing `Brush idx=102, 15, 14, 13, 11, 10, 9, 7`.
- **Every consumer then read that as a renderable index.** Delete tested
  `index < Count()` and otherwise fell back to `FindRenderableByCollisionVol` — with 150
  collision volumes and far fewer renderables, an index like `7` deleted renderable #7.
  The gizmo read its size from the collision volume and reported a merged **180x10x180
  slab** as the size of a small brush, which read as a brush being re-added on every
  click. The texture-apply path's own comment admitted it: *"g_sel.index may be a
  renderable index or a collision-volume index depending on which raycast produced it."*
- **Picking could also select an INVISIBLE AutoConvex box.** Every drawing path skips
  `SURF_COLLISION_PROXY`; the raycast did not. **Ctrl+D on a brush silently did
  nothing** — it cloned a collision volume, pushed it, then called
  `RebuildCollisionVolumes()`, which begins by clearing that same vector.
- `RaycastTestBrushes` and `FindRenderableByCollisionVol` are **gone**. Collision volumes
  are derived state, regenerated on every rebuild, so they were never sound to select.
- **Both bugs predate this work** — the delete branch is byte-identical at `b89`.

### Refactors

- **The editor now matches its designed layer tree** — `Core/`, `Subsystems/`,
  `Resources/`, `UI/`. `Main.cpp` went from **5,039 to ~2,165 lines**.
- **`EditorPanelState` moved to `Core/`.** It is 374 lines, read by everything
  (`PropsApply` alone touches 85 of its fields), and was declared in a UI header with its
  instance defined in `UI/UiCommon.hpp` — so any subsystem reading it would have had to
  link against the UI object just to reach the state. It is editor state, not a UI API
  surface.
- **`Resources/` created** ([8b085f0](https://github.com/odelyzid/angels-95-omega-tech/commit/8b085f0),
  [fd698a4](https://github.com/odelyzid/angels-95-omega-tech/commit/fd698a4)) —
  `AssetScope`, `PackageIO` and `AssetScan` as real translation units.
  `BuildAssetScope`, `PackIntoPackage` and `HotLoadPackage` were all implemented
  **inside `TexturePanel.cpp`** while `ModelPanel.cpp` also called them; they were shared
  only because the UI layer was one translation unit.
- **`tests/AssetScope.test.cpp`, 55 checks — the asset browser's first automated
  coverage.** It pins the invariant AGENTS.md states in prose with nothing behind it: a
  `.oz*` file on disk is a real file even when a package holds a same-named copy.
- **`actionApplyProperties` converted to a typed event** ([bd86b3e](https://github.com/odelyzid/angels-95-omega-tech/commit/bd86b3e)).
  **Action fields: 58 → 3.** The event carries the target only; the ~87 edited values stay
  live-read, because snapshotting 87 fields to write the ~6 that apply to any given
  selection is worse, and nothing can change a value between the Apply click and the
  same-frame drain.
- **Phase F, partially: 5 of 11 `Subsystems/` files are now real translation units**
  ([f0c10d7](https://github.com/odelyzid/angels-95-omega-tech/commit/f0c10d7),
  [3788873](https://github.com/odelyzid/angels-95-omega-tech/commit/3788873)) —
  `SurfaceOps`, `Placement`, `PropsApply`, `LevelState`, `History`. Fifteen
  functions/globals defined in headers without `inline` had to be fixed first; they are
  invisible in one translation unit and a multiple-definition link error the moment a
  second one includes them.
- **Three more accidental couplings the promotion exposed:** the document undo stacks
  were declared in `AnimEditing.cpp` and used in `History.cpp`; `SurfaceOps` called
  `SurfacePropsRefresh()` twice; `ApplyMapProperties` called `RefreshWorldGraph()` and
  carried a comment describing the very bug that call was working around. All corrected,
  and the two upward UI calls now happen in `Main.cpp`, which is the legal direction.
- **CI runs the test suites** and both AngelEd object lists are diffed against each other
  on every change — that check caught four Makefile rules with no matching `ci.yml` line
  before CI could hit it.

### Known gaps

Deliberate, and recorded in `Wiki/Editor-Architecture-Refactor.md`:

- **Phase F is parked at 5 of 11.** The remaining six (`Selection`, `EntityOps`,
  `WorldIO`, `OzoneExport`, `WorldGraphBridge`, `AnimEditing`) each need layer seams cut
  before promotion. `OzoneExport` is the clearest case — it calls UI file dialogs and
  uses Core statics, so promoting it means either declaring those across a layer
  boundary or leaving it a fragment.
- `Resources/AssetScope` does not yet mark which assets a level actually **uses**; the
  Texture Manager wants a third scope root for that, and it changes a signature 55 tests
  currently pin.
- The tileset filename table is not persisted, so a saved `texSlot=` cannot be resolved
  back to a path. Related: a tileset texture that fails to load is not pushed, so every
  later slot shifts down.
- The Texture Manager enumerates on its own rather than through `Resources/AssetScan`, and
  leaks an `HBITMAP` per thumbnail on rescan.
- AngelEd does not build on Linux (`AngelEd/Makefile` refuses). Scope is already sized.

### Downloads

**Standalone (run directly, no other files needed):**
- AngelServ-b90-linux-x86_64 / AngelServ-b90-windows-x86_64.exe - dedicated game server
- AngelMaster-b90-linux-x86_64 / AngelMaster-b90-windows-x86_64.exe - master/listing server
- OzPack-b90-linux-x86_64 / OzPack-b90-windows-x86_64.exe - asset packer CLI

**Requires the full System-b90.zip** (ships raylib/GLFW DLLs, GameData, INI templates, run scripts):
- Angels95-b90-linux-x86_64 / Angels95-b90-windows-x86_64.exe - game client
- AngelEd-b90-windows-x86_64.exe - editor (Windows only; Win32 native panels)

Platform notes:
- Linux binaries are dynamically linked against the distro glibc; run on a modern x86_64 Linux.
- `AngelEd` is Windows-only (Win32 API); there is no Linux build.
- For servers, see `System/angels95-serv.service` for VPS systemd units and `System/OzServer.ini` for config (`--bind 0.0.0.0` to accept remote clients).
