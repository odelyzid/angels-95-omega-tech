## Angels95 b89

Changes since [b88](https://github.com/odelyzid/angels-95-omega-tech/releases/tag/b88) - [compare](https://github.com/odelyzid/angels-95-omega-tech/compare/b88...b89)

A 12,000-line editor restructure and one silent world-data-loss bug. The bug is the
only thing here that changes what a level looks like; everything else is internal, and
the one behaviour change it does introduce is an improvement.

### Fixes

- **fix(world)**: stop the exporter from deleting every surface flag on re-export ([f536410](https://github.com/odelyzid/angels-95-omega-tech/commit/f536410))
- **Re-saving a level silently deleted every painted surface flag.** `ExportToOzone` emitted `flags=` only when the renderable's flags disagreed with `surfaceFlags` — but after a load they always agree, because one is derived from the other. So `flags=` was *never* written. Backdrop surfaces and AutoConvex collision proxies therefore vanished on every save. In `TestMap` alone that was **230 volumes**. `surface.def.flags` now owns the value and `surfaceFlags` is the derived mirror; the exporter asks `NeedsFlagsKwarg(defFlags)` instead of comparing a value to its own reflection. `AddBrushRenderable` had the same bug in the opposite direction and was writing a literal `flags=0`.
- **`GameData/Worlds/TestMap/World.ozone` is restored** — 229 proxies carry `flags=16` again (the 230th became a genuinely visible textured box, so it correctly has none). Pinned by `tests/Surface.test.cpp` (63/63) and `tests/OzoneParser.test.cpp` (28/28).

### Refactors

- **refactor(editor)**: a testable event bus, and CI now runs the test suites ([561a77b](https://github.com/odelyzid/angels-95-omega-tech/commit/561a77b))
- **`EditorPanelState` carried 58 hand-rolled `action*` message fields.** A panel's `WM_COMMAND` wrote a field, the frame loop polled all 58 once per frame, consumed, and reset — no envelope, no payload type, no record of who asked for what. Replaced with a typed bus (`ed::Event`, `std::variant`, raylib-free and Win32-free so it is testable headlessly). **58 fields → 4**, and all 4 remaining are documented exceptions with a reason. `tests/EditorEventBus.test.cpp` (77/77) is new. CI previously ran only `worldcheck`, which is why two suites had been sitting unexecuted.
- **Five live bugs found and fixed during the conversion**, all the same shape — an event that stored its target and then ignored it:
  - WorldGraph Delete/Duplicate read `g_sel` instead of the index they were given, so they acted on whatever was selected. Correct only because the select field happened to be written in the same `WM_NOTIFY`.
  - `actionWorldGraphProperties` was never read at all; it just called `OpenPropertiesForSelection()`.
  - `Reload` indexed `GetMeshObject()` with a foreign index and only checked the type afterwards.
  - `Convert to Animated` converted whatever was selected at drain time, not the mesh whose button was pressed.
  - The Pickups panel sent a list index resolved at drain time, so a panel rebuild between click and frame placed a different pickup.
- **Nine of the 58 fields had no writer at all** — ~110 lines of handler that could never run. Placement happened synchronously in the panel instead. Deleting them also orphaned the legacy light-apply handler (its only writer died with the b88 Light window), which is why that handler had been unreachable rather than merely unused.
- **refactor(editor)**: `Win32Dialogs.cpp` → `UI/`, `Main.cpp` → `Core/` + `Subsystems/` ([b9e919a](https://github.com/odelyzid/angels-95-omega-tech/commit/b9e919a), [715cab9](https://github.com/odelyzid/angels-95-omega-tech/commit/715cab9))
- Two 5,000-line god-files became `UI/` (17 files), `Core/` (6) and `Subsystems/` (7). Both entry points are single unity TUs that `#include` the real files beside them, so **build wiring did not change** — CI compiles AngelEd by hand, and N real objects would mean N Makefile rules plus N entries in a hand-maintained `g++` list that drifts silently. The cost is stated in the source: a fragment may use an include it does not state, and the include **order** is load-bearing.
- **refactor(editor)**: placement moved to `Subsystems/Placement`, closing the layer rule ([16957c9](https://github.com/odelyzid/angels-95-omega-tech/commit/16957c9))
- The Actor-Hierarchy panel called `PawnSystem::Add*` eight times and `ZoneManager::AddZone` once, directly from `WM_COMMAND`. It now validates and posts a typed `ed::Spawn*` event; the mutation moved to a subsystem. **Placement is now undoable** — it was the one editor mutation that pushed no history snapshot, while delete, duplicate and surface edit all did.
- The `Spawn*` seam and its payload already existed and were fully tested with **zero** users, so this filled a prepared seam rather than inventing one.

### Behaviour changes

- **Surface-flagged brushes were the visible casualty of the b88 lighting fix** and are unaffected here — but if you have re-saved a level since b88, **re-check it**: the export bug above deleted its backdrops and collision proxies. Re-saving is now safe.
- **Entity placement defers by one frame** instead of happening inside the button press. Placement is now undoable with Ctrl+Z.
- Nothing else observable changed. The editor was verified by machine (all 5 targets, 14 suites, worldcheck 0 errors) **and by hand** — a layer split produces no headless signal at all, so the manual pass was the load-bearing check.

### Docs

- `Wiki/Editor-Architecture-Refactor.md` — the plan, invariants, per-batch decisions and the R3/R4/R5 outcome records. **Read the "Ruled out" section before working on the editor**: several entries exist because a plausible-looking change reintroduces a bug or re-litigates a settled decision.
- Four false or imprecise claims in that document are corrected in this release, including one that had been load-bearing: it stated the old placement handlers "would have placed at `MainCamera.target` instead of the ghost position, so they were not merely redundant but *wrong*". `spawnPos` **is** `MainCamera.target`, refreshed every frame — they would have been identical. That mattered, because it was the main argument for keeping placement synchronous.
- `AGENTS.md` records the unity-TU convention, the one deliberate `UI/` → `Core/` back-edge, and the editor layer rule — with the note that the layer check must grep for *mutations*, since `UI/` legitimately holds a dozen read accessors and a bare `PawnSystem::` grep is all false positives.

### Known gaps

Deliberately left, recorded rather than hidden — all in the editor's internal structure, none user-visible:

- The `Resources/` layer from the original design was never created; asset discovery and packaging still live in `UI/`.
- `Core/EditorDispatcher.cpp` and `Core/EditorState.hpp` were never created — the dispatcher is still a switch inline in `main()`.
- `Subsystems/SurfaceOps` and `Subsystems/LevelState` were folded into `EntityOps.cpp` and `History.cpp` rather than created under those names.
- `actionApplyProperties` is still a field, though the plan twice promised otherwise.
