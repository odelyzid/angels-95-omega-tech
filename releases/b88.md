## Angels95 b88

Changes since [b87](https://github.com/odelyzid/angels-95-omega-tech/releases/tag/b87) - [compare](https://github.com/odelyzid/angels-95-omega-tech/compare/b87...b88)

### Refactors

- **refactor(editor)**: consolidate the property panels and drop the duplicate Zone/Light windows ([41e9678](https://github.com/odelyzid/angels-95-omega-tech/commit/41e9678c521801dfc3b5e34895f66e954e70c60f))
- **View > Zone Properties and View > Light Properties are gone.** Both duplicated state the Entity Properties panel already owned, and both were broken: Light Properties always applied to target `-1`, so its rows never reached the world, and Zone Properties was a level-global shader poke wearing a per-zone name (one global, no undo, fog pushed straight at `LitFog`). Zone and light editing is now right-click the entity > Properties. `F12` is unbound; `F4` and the toolbar **Zone** button still enter zone placement.
- **Level state moved to a `Map (level)` row** at the top of the WorldGraph: Game Mode, rules (max players, respawn, time limit, score limit, friendly fire), skybox + side skybox, and ambient particles including wind. The second `levelinfo` skybox path token used to be parsed and then silently dropped, so opening and re-saving a world deleted it; that is fixed, along with `timeLimitMinutes`, every non-default particle field and `gametype=<key>`.
- **Per-zone `envOverrides` are now editable** with live preview — fog colour/density/start/end, ambient colour/intensity and reverb mix/decay. The data was always honoured by the exporter, it just had no UI.
- **Fixed while wiring that preview:** `SurfaceMaterial` cached **no** fog locations although `Surface.fs` declares and uses all five, so surface-flagged brushes always fogged at the shader defaults (10/100, density 1) regardless of the level's fog. Its `UpdateFrame` also hardcoded `ambient = {0.1,0.1,0.1,1}` while the comment claimed the value lived on `OzoneLoader` — there was no accessor and it never read one, so a decorated brush was lit at a flat 0.1 in any room. Ambient and fog are now owned by `OzoneLoader` and mirrored from one point. **Surface-flagged brushes will render brighter and actually fog in the client — expect to re-tune.**
- **Entity Properties panel re-laid out:** one label width instead of a visible 22px step mid-panel, bold group headers with distinct control IDs (they all shared ID `1`), schema stats regrouped into Damage/Handling/Melee/Projectile/Viewmodel/Audio with the human label shown next to the raw `.ozls` key, and float rows right-aligned.
- **Portal deletion preserved.** The old Zone window owned the only route to `RemovePortal()`, so the panel's PORTAL section gained a Delete button. Deleting the selected portal now also clears the selection — portals shift down, so a retained target would have silently edited a different portal.

### Fixes

- **fix(multiplayer)**: guarantee a remote-player model and reconcile pickups with the server ([1ab9dc1](https://github.com/odelyzid/angels-95-omega-tech/commit/1ab9dc10c7f5bc503f3fcabe14a928b29ccfb430))
- **Remote players were invisible.** Imported meshes now opt out of backface culling: the FBX→glTF conversion bakes a Z-up → Y-up rotation that flips triangle winding, so a culled character model was *completely* missing while generated brush geometry (correct winding) was fine — which is why it read as missing content rather than a renderer bug. Culling state is also now tracked in one place; three modules each toggled it and each remembered the result in its own private bool. Remote players are additionally passed the real `OmegaTechData.Lights` instead of `{0}`, which put them outside the lighting pass entirely.
- **A failed model resolve no longer latches.** `oz::PlayerModel` falls back `Player.ozls` mesh → `Plague_Arcanist.glb` → `Character_Killer_01` → capsule, and a failed load now backs off 2 s and retries. Previously one unlucky early call — before the `.ozls` defs registered, or before a package hot-loaded — pinned the whole session to the capsule. `model_height` is authorable in `Player.ozls`; negative means "authored scale, do not normalise".
- **Networked pickups could be collected but never looked collected.** The collect flipped state on the *client's shadow* of the list, not on the drawn mesh, so the pickup never vanished and walking back re-requested an already-consumed one. The drawn node is now matched to the server by a file-order `netId`, and `PickupPawns` can hide it.
- **Every refused collect was a silent `return false`** with no log and no reply. `collect_pickup` now returns a reason (`UNKNOWN_PLAYER` / `WRONG_WORLD` / `UNKNOWN_WORLD` / `NOT_FOUND` / `OUT_OF_RANGE`), which is logged and answered with a re-sync of the player's own world — that turned the bug into a four-way guess.
- **Pickup state can no longer strand.** Three re-sync paths: the join snapshot, a 15 s per-player/own-world resync (UDP gives no delivery guarantee, so a single lost `PICKUP_RESPAWN` stranded a pickup permanently), and a client-initiated `PICKUP_RESYNC`. State re-syncs are world-scoped, and `netId == -1` ("not the server's") is left alone so a scripted pickup isn't hidden.
- **A client no longer drops every pickup message from an older server.** `PickupRespawnData::typeName` is an optional trailing field; gating on `sizeof()` made such a client discard them silently — a whole world's pickups at once. Gate on `net::kPickupRespawnSizeBase`. No protocol version bump.

Platform notes:
- Linux binaries are dynamically linked against the distro glibc; run on a modern x86_64 Linux.
- `AngelEd` is Windows-only (Win32 API); there is no Linux build.
- For servers, see `System/angels95-serv.service` for VPS systemd units and `System/OzServer.ini` for config (`--bind 0.0.0.0` to accept remote clients).
